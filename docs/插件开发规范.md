# Compositor 插件开发规范

> 本文档描述 Compositor-CN 内置插件系统的完整契约。按本文实现的插件可以装入
> [Compositor-CN](../README.md) 宿主（v4.1+，ABI v2）运行，无需重编译主程序。
>
> 两个完整参考实现随本仓库分发：
> **画布工具类** → [`撕边插件/TornEdgePlugin.swift`](../撕边插件/TornEdgePlugin.swift)（ABI v1）
> **导出类** → [`导出插件/WebExportPlugin.swift`](../导出插件/WebExportPlugin.swift)（ABI v2）
> 宿主权威实现：[`源码/Compositor/Plugins/CompositorPluginKit.swift`](../源码/Compositor/Plugins/CompositorPluginKit.swift)

## 1. 架构总览

```
宿主（Compositor.app）
  │  启动扫描 / 「导入插件」按钮
  ▼
.compositorplugin bundle（目录 / package）
  └── Contents/MacOS/<动态库>     ← 插件本体（一个 dylib）
        │ dlopen + dlsym("compositor_plugin_main")
        ▼
      entry 结构（手动偏移读取，56 字节 / ABI v2）
        ├── 元数据：identifier / name / SF Symbol / 参数 schema JSON
        ├── buildCutOutline  @40   ← 画布工具类（ABI v1 起）
        └── encodeImage      @48   ← 导出类（ABI v2 起）
```

- 插件是一个 `.compositorplugin` 后缀的目录（bundle），`Contents/MacOS/` 下放一个动态库；
  `Info.plist` 可选（不影响加载）。
- 接口为**纯 C ABI**：`strdup` 字符串 + 函数指针 + 两段式缓冲。宿主与插件之间**不传任何
  Swift 类型**——这是跨 Swift 编译器版本保持稳定的唯一保证。
- 参数值由宿主持久化（UserDefaults）并渲染配置 UI；算法逻辑全部在插件里。

## 2. 两种插件形态

| | 画布工具类 | 导出类 |
|---|---|---|
| schema `interaction` | `"rectangleSelect"` | `"export"` |
| 必须实现的函数 | `buildCutOutline`（@40） | `encodeImage`（@48） |
| 入口位置 | 左侧工具栏（按 `symbolName` 显示图标按钮） | 文件菜单（每插件一项「`<name>…`」） |
| 用户交互 | 复用选框工具的拖框交互与光标；按 **Delete** 触发 | 参数面板 + 实时预览 + 保存对话框 |
| 参考实现 | TornEdgePlugin.swift | WebExportPlugin.swift |

一个插件可以同时实现两个函数（宿主按 `interaction` 决定入口位置，另一个函数不会被调用）。

## 3. ABI 契约（权威定义）

### 3.1 入口

```c
// 宿主调用：dlsym(handle, "compositor_plugin_main")
// 参数：宿主 ABI 版本（当前 1）；返回：entry 结构指针（进程期存活，宿主不释放）
void* compositor_plugin_main(uint32_t hostABI);
```

### 3.2 entry 结构布局（手动偏移读取，不要假设 Swift struct 跨 bundle 布局）

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| @0  | `uint32_t` | `abiVersion` | 本插件实现的 ABI 版本：`1`（48 字节）或 `2`（56 字节） |
| @8  | `const char*` | `identifier` | 插件唯一标识（如 `"torn-edge"`）；**全局唯一**，同 id 先到先得 |
| @16 | `const char*` | `name` | 显示名（如 `"Torn Edge"`）；宿主经词表 `L()` 查本地化 |
| @24 | `const char*` | `symbolName` | SF Symbol 名（如 `"scissors"`）；缺省 `puzzlepiece.extension` |
| @32 | `const char*` | `paramsJSON` | 参数 schema（§4） |
| @40 | 函数指针 | `buildCutOutline` | 画布工具类（§5）；不实现置 `NULL` |
| @48 | 函数指针 | `encodeImage` | 导出类（§6）；**仅 ABI ≥ 2 有效**，不实现置 `NULL` |

**向后兼容**：宿主对 `abiVersion = 1` 的插件只读前 48 字节（`encodeImage` 视为 NULL）。
声明 `abiVersion = 2` 即可同时获得两类能力。

字符串全部为 UTF-8 C 字符串（`strdup` 或字面量指针均可，进程期存活）。

### 3.3 内存所有权

- `encodeImage` 的输出缓冲由**插件 `malloc`、宿主 `free`**（同一 libSystem 分配器）。
- entry 结构与元数据字符串由**插件持有**，进程期存活，宿主不释放。
- `buildCutOutline` 的输出缓冲由**宿主分配**（两段式，见 §5）。

## 4. 参数 schema（paramsJSON）

宿主用它渲染配置 UI（分段选择器 / 可拖拽滑杆 + 数字框 / 骰子按钮）并做参数持久化。

```jsonc
{
  "interaction": "rectangleSelect",   // "rectangleSelect"（画布类）| "export"（导出类）
  "params": [
    {
      "key": "profile",               // 参数键（传给插件的 JSON 对象键名）
      "label": "Style",               // 显示名（宿主经 L() 查词表，缺词条时原样显示）
      "group": "shared",              // 分组：shared 常显；其余按 §4.1 显隐
      "type": "choice",               // "float" | "int" | "choice"
      "choices": ["rough", "fine"],   // choice 专用：选项值
      "choiceLabels": ["Rough","Fine"],// choice 专用：显示名（缺省 = choices）
      "default": "rough",             // choice 的 default 是【选项字符串】
      "presets": { ... }              // 仅 preset 参数用，见 §4.2
    },
    {
      "key": "roughAmp",
      "label": "Amplitude",
      "group": "rough",
      "type": "float",                // float/int 渲染为滑杆 + 数字框
      "min": 0, "max": 120,
      "default": 42,                  // 数值类型的 default 是数字
      "suffix": "px",                 // 可选：数字框后缀（"px" / "%" / "/950px"…）
      "dice": true                    // int 专用：显示骰子按钮（随机种子场景）
    }
  ]
}
```

### 4.1 分组显隐规则

- `group = "shared"` 的参数**常显**；
- `choice` 类型参数的**当前选项值**决定显示哪组：选项值 = 组名（如 `profile` 选 `"rough"`
  时显示 `group: "rough"` 的参数 + 全部 shared 参数）。可多级嵌套（Web 导出插件的
  `pngMode` → `palette` 组即二级示例）；
- 组内无参数时不渲染该组。

### 4.2 档位预设（presets）

在某个 `choice` 参数上加 `"presets"` 字段，宿主在用户切换档位时**批量填参**：

```jsonc
{"key":"preset","type":"choice",
 "choices":["high","standard","extreme","custom"],
 "presets":{
   "high":     {"quality":92, "scale":100, ...},  // 档位名 → { 参数 key: 值 }
   "standard": {...},
   "custom":   {}                                 // 空对象 = 保留现状
 }}
```

- 手动改任何参数与档位预设不符时，宿主自动把 preset 跳回「自定」档（Web 导出插件行为）；
- preset 的选项值必须也在 `choices` 里。

### 4.3 运行时注入

宿主传给插件的参数 JSON = **当前全部参数值**（choice 传选项字符串、int 传整数、float 传小数）
外加画布类插件的 `lb0`–`lb3`（图层可见像素边界，文档坐标，见 §5.3）。键序随机（宿主侧
JSONSerialization 键序轮换），**按 key 解析，不要假设键序**。

## 5. 画布工具类：buildCutOutline

**语义**：用户框选 → 按 Delete → 插件根据选框几何与参数生成「撕掉区域」的闭合轮廓点集，
宿主把它转成 CGPath 后以 `destinationOut` 从图层像素中擦除（自动进撤销历史）。

```c
// 返回 0 成功 / 1 参数错误 / 2 缓冲不足（ioCount 回填所需点数）
int buildCutOutline(const float* rect,            // 8 floats：x0,y0, x1,y0, x1,y1, x0,y1（顺时针四角，文档坐标）
                    const char* paramsJSON,       // §4.3 的运行时参数对象
                    float* outPoints,             // (x,y) 交错点集；第一次调用传 NULL
                    int32_t* ioCount);            // 入：缓冲容量（点数）；出：实际点数
```

### 5.1 两段式调用协议（宿主固定这样调用）

1. 宿主先以 `outPoints = NULL` 调用 → 插件把**所需点数**写入 `*ioCount`，返回 0；
2. 宿主按点数分配缓冲（`count × 2` 个 float）后第二次调用 → 插件填点，返回 0。

两次调用必须得到**逐点一致**的结果（算法由种子决定、无隐藏状态）。宿主拒绝点数
`count > 8,000,000` 的输出。

### 5.2 点集约定

- `(x, y)` 交错的 float 数组，**文档坐标系**（与画布像素一致）；
- 顺序 = 沿轮廓环绕（撕边插件为上边 → 右边 → 下边 → 左边顺时针）；宿主 `fillPath`
  自动闭合，相邻边端点的间隙由填充规则自然衔接；
- 轮廓可以超出选框（撕边毛边允许跨出选框），宿主的擦除不受选框裁剪。

### 5.3 齐平裁切（lb0–lb3）

宿主会把图层可见边界（`layer.transform` 矩形 ∩ 画布，仅无旋转图层）注入参数对象的
`lb0`(minX) / `lb1`(minY) / `lb2`(maxX) / `lb3`(maxY)。插件据此实现「选框边与图层边缘
齐平 → 该边直线全像素裁切不撕」等效果（容差建议 2 文档像素）；不需要此特性的插件
忽略这四个键即可。

## 6. 导出类：encodeImage

**语义**：宿主把合成后的画布像素交给插件编码，返回编码后的完整文件字节流
（如 WebP / JPEG / GIF 文件内容）。

```c
// 返回 0 成功 / 1 参数错误 / 2 编码失败（errBuf 必须写入英文错误说明）
int encodeImage(const uint8_t* rgba,        // RGBA8 预乘像素
                int32_t width, int32_t height,
                int32_t bytesPerRow,        // 每行字节数（可能与 w*4 不等，必须遵守）
                const char* paramsJSON,
                uint8_t** outData,          // 出：插件 malloc 的缓冲
                unsigned long* outLength,   // 出：输出字节数
                char* errBuf,               // 出：错误说明（英文，NUL 结尾）
                int32_t errBufSize);        // 宿主给 256
```

- **输入**：RGBA8 **预乘**像素（需要透明信息时自行反预乘；参考 WebExportPlugin 的做法）；
- **输出**：插件 `malloc`，宿主拷贝为 Data 后立即 `free`；
- **线程**：宿主在**后台线程**调用（预览 debounce 300ms + 保存时各一次），插件不得触碰
  MainActor / UI 状态，需要线程安全；
- **错误路径必须可见**：失败时返回非 0 并写 errBuf——绝不要静默返回空数据。

宿主侧封装参考：`CompositorPluginKit.encodeWithPlugin(...)`。

## 7. bundle 打包与签名

### 7.1 目录结构

```
TornEdge.compositorplugin/          ← 目录名随意，后缀必须 .compositorplugin
└── Contents/
    └── MacOS/
        └── TornEdgePlugin          ← 编译出的动态库（文件名随意）
```

### 7.2 编译命令（Swift 插件模板）

```bash
xcrun swiftc -O -swift-version 5 -parse-as-library \
  -target "arm64-apple-macos26.5" \
  -sdk "/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk" \
  TornEdgePlugin.swift \
  -emit-library -o TornEdgePlugin \
  -Xlinker -install_name -Xlinker @rpath/TornEdgePlugin
```

要点：

- **Swift runtime 随 macOS 内置且宿主进程已加载**，插件直接复用，产物只有 libc/libSystem；
- 撕边类插件可以做到**零 Foundation 依赖**（手写扁平 JSON 解析，参考 TornEdgePlugin）；
  需要 heavier 运行时（ImageIO / CoreGraphics）时正常 import 即可——宿主进程内
  Foundation 必然已加载，无额外成本（参考 WebExportPlugin）；
- 第三方 C 库先 `clang -c` 编成 arm64 静态库再随插件链接（参考导出插件的 libwebp 管线）；
- 装入 App 包内 `Contents/Plugins/` 后需**重签主 bundle**（ad-hoc + 沙盒授权 +
  `com.apple.security.cs.disable-library-validation`），两个编译脚本末尾都有现成实现；
- 装入用户插件目录（`~/Library/Application Support/Compositor/Plugins/`）则**不需要重签 App**。

### 7.3 用别的语言写插件

C ABI 不关心实现语言：纯 C / C++ / Rust（`#[no_mangle]` + `extern "C"`）都可以，
编译成 dylib 放进 bundle 即可。schema 与参数协议不变。

## 8. 安装与加载规则

宿主按序扫描两个目录，**同 identifier 先到先得**：

| 优先级 | 目录 | 装入方式 |
|---|---|---|
| 1 | `~/Library/Application Support/Compositor/Plugins/` | App 内「导入插件」按钮（复制 + 立即加载，失败自动回滚） |
| 2 | App 包内 `Contents/Plugins/` | 编译脚本（需要重签主 bundle） |

- **更新插件**：向导入按钮再选一次同名 bundle → 新文件进入用户目录；若旧版正在运行态，
  弹「插件已更新，重启后生效」（dyld 对已加载 dylib 只返回旧 handle）；
- **加载失败的插件不会残留**（导入路径会删除副本并还原被覆盖的旧版）；
- 加载失败原因会出现在宿主的 `loadErrors`（缺 dylib / 缺入口 / ABI 不兼容 / schema 非法 JSON）。

## 9. 实战注意事项（踩坑清单）

以下全部来自本仓库两个插件的实际开发与排查记录：

1. **C ABI 纪律**：不要在 entry 结构里放 Swift 类型/泛型/闭包；字符串用 C 字符串；
   布局靠手动偏移约定，不要依赖 Swift struct 的自动布局跨 bundle 相等。
2. **choice 的 default 是字符串**：宿主按 `choices.firstIndex(of: default)` 映射索引；
   写成数字会被当数值解析导致档位错位（v4.1 实测修复过）。
3. **参数 JSON 键序随机**：宿主侧 JSONSerialization 键序做了轮换随机化。插件按 key
   解析；如果插件侧也要「比较两次参数是否相同」（如预览缓存），用**键序固定的拼接串**，
   不要用序列化输出直接比较（v4.2 预览卡死事故的根因）。
4. **宿主参数持久化必须走 @Observable 链路**（宿主职责，插件无感）：runtimeValues 内存
   缓存 + UserDefaults 落盘；choice 持久化的是选项索引。
5. **确定性**：带随机性的效果算法必须由种子完全决定（SplitMix64 之类），两段式调用
   两次结果逐点一致——宿主会连续调两次。
6. **encodeImage 是后台线程**：不要在里面碰 UI / MainActor；大缓冲注意 bytesPerRow。
7. **错误要可见**：`encodeImage` 失败必须写 errBuf 返回非 0；静默失败在 GUI 上表现为
   永久转圈，极难排查。
8. **插件文案与词表**：宿主渲染 `name` / `label` 时会走 `L()` 查 `Localizable.strings`，
   查不到原样显示英文。想让插件界面中文化，可以把词条提交给本项目词表（或在自己的
   fork 中扩展词表）——词表校验脚本会检查显式 key 的完整性。
9. **identifier 全局唯一**：用反域名风格（`com.yourname.effect-x`）或带产品前缀的
   kebab-case（`torn-edge`、`web-export`），避免与其他插件冲突。
10. **SF Symbol 选型**：`symbolName` 必须是 macOS 自带 SF Symbols 名称；工具栏按钮
    小尺寸渲染，选轮廓清晰的图标。个别系统符号会被本地化字形渲染成汉字（如
    `textformat` 在简中系统显示「格式」），截图验证实际渲染效果。

## 11. FAQ

**Q：插件能访问文件系统 / 网络吗？**
A：技术上受宿主沙盒授权约束。宿主是沙盒 App，插件随宿主进程运行，只有用户显式选择的
文件（打开/保存面板）可写。不要在插件里做网络请求——破坏用户信任且过不了审查。

**Q：宿主升级后我的插件会失效吗？**
A：C ABI 的设计目标就是跨版本稳定。宿主只向后兼容（abiVersion 只增不改语义）；
`abiVersion = 1` 的插件在任何 ≥ v4.1 的宿主上都有效。

**Q：能做没有 UI 的纯后台插件吗？**
A：当前两种形态都自带 UI 入口（工具栏 / 文件菜单）。无参数插件给一个空 `params: []`
即可，UI 只显示按钮本身。

**Q：如何调试？**
A：先用 Python ctypes / Swift dlopen 直调入口做冒烟测试（参考开发日志里的 ABI 冒烟
测试方法）；GUI 层调试用「导入插件」按钮 + 宿主 loadErrors 反馈，加载失败原因会完整返回。
